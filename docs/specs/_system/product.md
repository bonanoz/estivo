# Карточка товара

Страница /product/<slug>/: описание и характеристики товара, выбор цвета отделки, кнопки «В корзину» и «Оформить заявку» или «Узнать цену», галерея или 3D-модель, похожие товары, показ и приём отзывов.

## Требование: открытие страницы товара
Система ДОЛЖНА по адресу /product/<slug>/ показывать крошки «Главная / Каталог / <материал> / <название>», бейджи, название, сердечко избранного, ссылку на отзывы, цену «от N ₽» с зачёркнутой старой ценой, краткое описание, список доверия (гарантия N лет со ссылкой на /garantiya/, сроки, доставка ТК, ручная работа), раскрывающиеся блоки, описание, строку фактов, отзывы и «Вам может подойти» — до 4 показываемых товаров той же категории.

- Сценарий «обычный товар»: КОГДА пользователь открывает /product/<slug>/ ТОГДА видит H1 с названием, цену «от N ₽», ссылку «Гарантия 3 года» и блок «Размеры и характеристики» раскрытым
- Сценарий «похожие»: КОГДА в категории есть ещё 5 показываемых товаров ТОГДА в «Вам может подойти» видно 4, текущего среди них нет
- Сценарий «без описания»: КОГДА у товара пустое описание ТОГДА секции «Описание» нет
- Сценарий «неизвестный товар»: КОГДА пользователь открывает /product/net-takogo/ ТОГДА получает 404 (если пути нет в карте редиректов Tilda)
- Сценарий «снятый товар»: КОГДА товар снят с показа в админке и пользователь открывает его прямую ссылку ТОГДА страница отдаётся с кнопками покупки

[?] Страница не проверяет, показывается ли товар: снятый товар открывается с кнопками «В корзину» и «Оформить заявку», а их POST на /cart/add/<id>/ отвечает 404 (views.py:301-305, views.py:414); сердечко на такой странице тоже 404 (views.py:512-513)

## Требование: характеристики
Система ДОЛЖНА в блоке «Размеры и характеристики» показывать нагрузку «до N кг», «каркас — металл, порошковая окраска», оба срока; температуру «−50…+50°C» только у ротанга (или товара без материала) и только когда заданы обе границы; габариты «Д × Ш × В см» с «—» на месте пустых, если задано хотя бы одно; вес, если задан.

- Сценарий «ротанг»: КОГДА пользователь открывает товар из ротанга с границами −50 и +50 ТОГДА видит «Температура эксплуатации −50…+50°C»
- Сценарий «роуп»: КОГДА у товара из роупа заданы границы температуры ТОГДА строки температуры нет
- Сценарий «частичные габариты»: КОГДА у товара задана только длина 120 ТОГДА видна строка «120 × — × — см»
- Сценарий «нет габаритов»: КОГДА не задано ни одного размера ТОГДА строки габаритов нет

## Требование: выбор цвета отделки
Система ДОЛЖНА показывать цвета товара группами «Плетение», «Подушки», «Каркас» (пустые группы скрыты) переключателями; по умолчанию выбран первый цвет группы, подпись «<группа>: <цвет>» следует за выбором. С JS выбор пишется в адрес (?weave=, ?cushion=, ?frame=) и восстанавливается при перезагрузке; цвет из чужой группы или не привязанный к товару игнорируется. Под цветами — «Цвет не влияет на цену».

- Сценарий «предвыбор из адреса»: КОГДА пользователь открывает /product/<slug>/?weave=<id второго цвета плетения> ТОГДА выбран второй цвет и подпись «Плетение: <его название>»
- Сценарий «смена цвета»: КОГДА пользователь выбирает другой цвет подушек ТОГДА адрес получает cushion=<id> без перезагрузки, после F5 выбор сохраняется
- Сценарий «чужой цвет»: КОГДА пользователь открывает ?weave=<id цвета, не привязанного к товару> ТОГДА выбран первый цвет группы
- Сценарий «цвет другой группы»: КОГДА пользователь открывает ?weave=<id цвета подушек> ТОГДА выбор плетения по умолчанию
- Сценарий «мусор»: КОГДА пользователь открывает ?weave=abc ТОГДА страница 200, выбор по умолчанию
- Сценарий «нет группы»: КОГДА у товара из ротанга нет цветов каркаса ТОГДА группы «Каркас» нет

## Требование: кнопки покупки
Система ДОЛЖНА у товара с ценой показывать «В корзину — N ₽» (с JS добавляет без перезагрузки и открывает выезжающую корзину, без JS ведёт на /cart/) и «Оформить заявку» (добавляет позицию с выбранными цветами и ведёт на /cart/checkout/). У товара с ценой 0 — «Цена по запросу» и «Узнать цену» на /kontakty/?product=<slug>, без формы корзины. На телефоне после прокрутки ниже кнопок появляется липкая панель с теми же двумя кнопками.

- Сценарий «в корзину с JS»: КОГДА пользователь нажимает «В корзину — 45 000 ₽» ТОГДА выезжает панель «Ваша заявка» с «Добавлено в заявку: <название>», счётчик корзины в шапке растёт
- Сценарий «повторное нажатие»: КОГДА запрос добавления ещё идёт ТОГДА кнопка недоступна и второй запрос не уходит
- Сценарий «оформить заявку»: КОГДА пользователь нажимает «Оформить заявку» ТОГДА позиция с выбранными цветами в корзине и открыт /cart/checkout/
- Сценарий «без JS»: КОГДА JS выключен и пользователь нажимает «В корзину» ТОГДА попадает на /cart/ с этой позицией
- Сценарий «цена по запросу»: КОГДА пользователь открывает товар с ценой 0 ТОГДА видит «Цена по запросу» и «Узнать цену», кнопок корзины нет
- Сценарий «липкая панель»: КОГДА на ширине 390px пользователь прокручивает ниже основных кнопок ТОГДА внизу экрана видны «В корзину» и «Оформить заявку»

## Требование: галерея и 3D-модель
Система ДОЛЖНА при загруженной 3D-модели показывать вращаемую модель с подсказкой «Вращайте модель…» и подгружать модуль 3D только на этой странице; без модели — главное фото (или заглушку) и ленту миниатюр, если есть дополнительные фото; нажатие на миниатюру меняет главное фото.

- Сценарий «галерея»: КОГДА у товара 3 дополнительных фото и пользователь нажимает вторую миниатюру ТОГДА главное фото меняется, миниатюра помечена текущей
- Сценарий «3D»: КОГДА у товара есть модель .glb ТОГДА вместо фото показана вращаемая модель
- Сценарий «без модели»: КОГДА модели нет ТОГДА скрипт 3D на страницу не подключается

## Требование: показ отзывов
Система ДОЛЖНА показывать в блоке «Отзывы» (якорь #reviews) только опубликованные отзывы товара: среднюю оценку с одним знаком после запятой, число со склонением («1 отзыв», «3 отзыва», «5 отзывов»), автора, звёзды, срок использования, текст. Без отзывов — «Отзывов пока нет. Станьте первым.»; ссылка под названием товара ведёт на #reviews.

- Сценарий «есть отзывы»: КОГДА у товара 2 опубликованных отзыва с оценками 4 и 5 ТОГДА видно «4,5» и «2 отзыва»
- Сценарий «неопубликованный»: КОГДА у товара есть только неопубликованный отзыв ТОГДА видно «Отзывов пока нет»
- Сценарий «ссылка на отзывы»: КОГДА пользователь нажимает рейтинг под названием ТОГДА страница прокручивается к блоку «Отзывы»

## Требование: отправка отзыва
Система ДОЛЖНА по кнопке «Написать отзыв» раскрывать форму: имя, оценка от 1 до 5, срок использования (необязательно), текст. Отзыв сохраняется неопубликованным, без уведомления в Telegram. С JS форма заменяется сообщением «Спасибо за отзыв… на модерацию»; без JS — возврат на товар с сообщением «Спасибо! Отзыв отправлен на модерацию.». При ошибках форма остаётся раскрытой с подсказками у полей и введёнными данными.

- Сценарий «отзыв с JS»: КОГДА пользователь заполняет форму на /product/<slug>/ и жмёт «Отправить отзыв» ТОГДА форма сменяется текстом про модерацию, отзыв в админке неопубликованный
- Сценарий «отзыв без JS»: КОГДА JS выключен и форма отправлена ТОГДА пользователь возвращается на товар и видит «Спасибо! Отзыв отправлен на модерацию.»
- Сценарий «оценка вне диапазона»: КОГДА пользователь отправляет оценку 0 или 6 ТОГДА у поля оценки ошибка, отзыв не создан
- Сценарий «пустая форма»: КОГДА пользователь отправляет пустую форму ТОГДА ошибки у имени, оценки и текста, отзыв не создан
- Сценарий «ловушка для ботов»: КОГДА заполнено скрытое поле «Сайт» ТОГДА ответ как при успехе, отзыв не создан
- Сценарий «неизвестный товар»: КОГДА клиент делает POST /product/net-takogo/review/ ТОГДА получает 404
- Сценарий «не тот метод»: КОГДА клиент делает GET /product/<slug>/review/ ТОГДА получает 405
- Сценарий «лимит»: КОГДА с одного IP за 10 минут уходит шестой POST отзыва ТОГДА ответ 429 «Слишком много запросов, попробуйте позже.»

[?] Ошибки формы отзыва не связаны с полями: нет aria-invalid и aria-describedby, у текста ошибки нет id (forms.py:88, _review_form.html:10, :15, :21, :26), хотя design-system.md:198 требует связь для всех полей; лид-форма и оформление заявки это делают
