# SEO

Мета-теги и заголовки страниц, canonical и Open Graph на основном домене, разметка товара, sitemap.xml, robots.txt и редиректы со старых адресов Tilda.

## Требование: заголовки и описания страниц
Система ДОЛЖНА выдавать каждой публичной странице свой title и meta description: раздел материала — «<Материал> — каталог | ESTIVO», раздел категории — «<Категория> из <материала> — купить в Тольятти и Самаре | ESTIVO», товар — «<Название> из <материала> | ESTIVO» (без «из …», если материал уже в названии), описание товара — краткое описание или начало описания; у остальных страниц — свой текст или общий по умолчанию. Язык страницы — русский, H1 один.

- Сценарий «категория»: КОГДА пользователь открывает /catalog/rotang/kresla/ ТОГДА title «Кресла из ротанга — купить в Тольятти и Самаре | ESTIVO»
- Сценарий «товар»: КОГДА пользователь открывает товар «Кресло Кокон» из ротанга ТОГДА title «Кресло Кокон из ротанга | ESTIVO»
- Сценарий «материал в названии»: КОГДА товар называется «Диван из роупа Милан» ТОГДА title без повторного «из роупа»
- Сценарий «все страницы»: КОГДА проверяются все адреса из sitemap и /cart/, /wishlist/, /cart/checkout/ ТОГДА у каждой 200, один H1, meta description и canonical

Решение владельца 02.11.2026: «купить» в title разрешено — title виден только в поиске, запрет docs/design-system.md §5 касается текстов на страницах. В design-system.md нужно дописать это исключение (views.py:258).

## Требование: canonical и Open Graph
Система ДОЛЖНА строить canonical и og:url из пути страницы без параметров на основном домене (SITE_URL, по умолчанию https://estivo63.ru), даже если сайт открыт с другого хоста; og:image товара — его фото или заглушка, главной — фото первого экрана; ссылки на файлы во внешнем хранилище остаются как есть.

- Сценарий «другой хост»: КОГДА сайт открыт с *.onrender.com ТОГДА canonical и og:url указывают на https://estivo63.ru/<путь>
- Сценарий «фильтры»: КОГДА пользователь открывает /catalog/?flag=new ТОГДА canonical https://estivo63.ru/catalog/

[?] canonical всегда без параметров, поэтому страницы ?page=2 и дальше канонизируются на первую; товары глубже первой страницы находятся поиском только через sitemap (base.html:12)

## Требование: разметка товара
Система ДОЛЖНА на странице товара отдавать разметку schema.org Product: название, описание, артикул (если есть), фото (если есть), материал, бренд ESTIVO, предложение с ценой в рублях и наличием, а при опубликованных отзывах — средняя оценка и их число.

- Сценарий «с отзывами»: КОГДА у товара 2 опубликованных отзыва ТОГДА в разметке aggregateRating с ratingValue и reviewCount 2
- Сценарий «без отзывов»: КОГДА опубликованных отзывов нет ТОГДА aggregateRating нет

[?] У товара «Цена по запросу» разметка отдаёт "price": "0" — поисковик может показать цену 0 ₽ (product_detail.html:28); у снятого с показа товара availability = PreOrder (product_detail.html:30)

## Требование: sitemap.xml и robots.txt
Система ДОЛЖНА отдавать /sitemap.xml с адресами на основном домене: все показываемые товары (с датой изменения), разделы материалов и пар «материал + категория», где есть показываемые товары, и статичные страницы (главная, каталог, бизнес, дизайнеры, о нас, доставка, гарантия, FAQ, контакты, политика). /robots.txt разрешает всё, кроме /admin/ и /order/, и указывает адрес sitemap.

- Сценарий «sitemap»: КОГДА клиент открывает /sitemap.xml ТОГДА видит https://estivo63.ru/privacy/, /catalog/rotang/kresla/ и товары
- Сценарий «снятый товар»: КОГДА товар снят с показа ТОГДА его адреса нет в sitemap, а раздел без других товаров тоже пропадает
- Сценарий «robots»: КОГДА клиент открывает /robots.txt ТОГДА видит «Disallow: /order/» и «Sitemap: https://estivo63.ru/sitemap.xml»

## Требование: редиректы со старых адресов Tilda
Система ДОЛЖНА на адреса, которых нет на сайте, отвечать по карте старых адресов одним переходом без цепочек (со слэшем на конце и без): 301 на новый адрес или 410. Адрес товара Tilda «…/tproduct/<id>-…» ведёт на текущий адрес товара с этим id Tilda, даже после смены slug; если товар из карты не импортирован — на раздел каталога. /news/tpost/… ведёт на /. Существующие адреса сайта не перехватываются.

- Сценарий «раздел»: КОГДА клиент открывает /aksessuary ТОГДА 301 на /catalog/rotang/aksessuary/
- Сценарий «акции»: КОГДА клиент открывает /promo ТОГДА 301 на /catalog/?flag=sale
- Сценарий «товар по id Tilda»: КОГДА клиент открывает /tproduct/123456789-kreslo и у товара сменили slug ТОГДА 301 на новый /product/<slug>/
- Сценарий «блог»: КОГДА клиент открывает /news/tpost/lyuboy-adres ТОГДА 301 на /
- Сценарий «удалённое»: КОГДА клиент открывает адрес демо-товара из карты ТОГДА 410
- Сценарий «нет в карте»: КОГДА клиент открывает /nikogda-ne-bylo ТОГДА 404
- Сценарий «живой адрес»: КОГДА клиент открывает /catalog/ ТОГДА 200 без редиректа
