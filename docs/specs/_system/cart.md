# Корзина

Сессионная корзина без регистрации: добавление с товара, выезжающая панель после добавления, страница /cart/, изменение количества, удаление с возвратом, пустое состояние и счётчик в шапке. Из корзины собирается одна заявка (см. checkout.md).

## Требование: состав корзины
Система ДОЛЖНА хранить корзину в сессии браузера без регистрации. Позиция — это товар плюс вариант (размер и столешница, если у товара есть варианты) плюс набор выбранных цветов: то же сочетание увеличивает количество, другое даёт новую строку. Цена строки — цена варианта, у товара без вариантов — цена товара; она всегда берётся из базы. Количество на позицию — от 1 до 99. Принимаются только цвета, привязанные к товару и подходящие по группе; вариант не этого товара, пустой или мусорный заменяется первым вариантом, у товара без вариантов поле варианта игнорируется. Строка с удалённым вариантом не показывается и не входит в итог. Строки, добавленные до появления вариантов, работают как раньше. Товар с ценой 0 и не показываемый на сайте в корзину не попадает.

- Сценарий «два цвета — две строки»: КОГДА пользователь добавляет кресло с плетением «Графит», затем с плетением «Беж» ТОГДА на /cart/ две строки
- Сценарий «тот же цвет»: КОГДА пользователь дважды добавляет кресло с одним и тем же набором цветов ТОГДА на /cart/ одна строка с количеством 2
- Сценарий «огромное количество»: КОГДА клиент делает POST /cart/add/<id>/ с quantity=1000000000000 ТОГДА в строке 99
- Сценарий «мусорное количество»: КОГДА клиент отправляет quantity=-3 или quantity=abc ТОГДА добавляется 1 штука
- Сценарий «чужой цвет»: КОГДА клиент отправляет color_weave=<id цвета, не привязанного к товару> ТОГДА позиция добавляется без этого цвета
- Сценарий «два размера»: КОГДА пользователь добавляет стол «160×90 см / Стекло» (54 900) и «80×80 см / HPL compact» (29 900) ТОГДА на /cart/ две строки, «Итого 84 800 ₽»
- Сценарий «чужой вариант»: КОГДА клиент отправляет variant=<id варианта другого товара>, variant=abc или не отправляет его ТОГДА в корзине первый вариант этого стола по его цене
- Сценарий «вариант удалили»: КОГДА вариант в корзине и его удалили в админке ТОГДА строки нет на /cart/, итог и счётчик без неё
- Сценарий «цена по запросу»: КОГДА клиент делает POST /cart/add/<id товара с ценой 0>/ ТОГДА корзина пуста, ответ ведёт на /kontakty/?product=<slug> (с JS — заголовком перехода)
- Сценарий «снятый или несуществующий товар»: КОГДА клиент делает POST /cart/add/<id снятого товара>/ или /cart/add/999999/ ТОГДА получает 404, корзина не меняется
- Сценарий «не тот метод»: КОГДА клиент делает GET /cart/add/<id>/ ТОГДА получает 405
- Сценарий «цена стала по запросу»: КОГДА товар уже в корзине и его цену обнулили ТОГДА строка остаётся, на /cart/, в панели и на оформлении вместо суммы «Цена по запросу», итог без неё; если других строк нет, в «Итого» тоже «Цена по запросу»

## Требование: ответ на добавление
Система ДОЛЖНА после добавления с JS открывать выезжающую панель-диалог «Ваша заявка» с «Добавлено в заявку: <название>» и ссылкой «Открыть», строками, итогом, «Перейти к заявке», «Продолжить покупки» (закрывает панель), «Открыть корзину» и «Вам может понравиться» — до 4 товаров той же категории. Панель закрывается крестиком, Esc и кликом по затемнению, фокус удерживается внутри. Без JS — переход на адрес из поля next, если он с этого сайта, иначе на /cart/.

- Сценарий «панель»: КОГДА пользователь на товаре нажимает «В корзину» ТОГДА справа выезжает «Ваша заявка» с этим товаром и итогом
- Сценарий «закрытие»: КОГДА панель открыта и пользователь жмёт Esc ТОГДА панель закрывается
- Сценарий «Tab в панели»: КОГДА панель открыта и пользователь жмёт Tab много раз ТОГДА фокус не уходит на страницу под панелью
- Сценарий «свой next»: КОГДА без JS отправлен POST /cart/add/<id>/ с next=/catalog/ ТОГДА переход на /catalog/
- Сценарий «чужой next»: КОГДА без JS отправлен POST /cart/add/<id>/ с next=https://evil.example/ или next=//evil.example ТОГДА переход на /cart/

## Требование: страница корзины
Система ДОЛЖНА на /cart/ показывать строки (фото, название-ссылка, выбор — «Размер: …», «Столешница: …», затем цвета, «от N ₽ / шт», кнопки «−»/«+», сумма строки, «Удалить») и итог: «Товаров N», «Итого N ₽», пояснение «Это предварительный расчёт. Оплаты на сайте нет…», факты (отгрузка в течение 3 дней, изготовление от 4 недель, доставка ТК до двери, гарантия 3 года со ссылкой, оплата 50% + 50%), «Перейти к заявке» и текстовую ссылку «Продолжить покупки». Строки снятых с показа товаров не выводятся и не входят в итог.

- Сценарий «две позиции»: КОГДА пользователь с двумя позициями открывает /cart/ ТОГДА видит обе строки, «Итого» равен сумме строк, кнопка «Перейти к заявке» ведёт на /cart/checkout/
- Сценарий «тексты»: КОГДА пользователь открывает /cart/ ТОГДА на странице нет слов «заказ», «купить», «оплатить», кроме срока «под заказ»
- Сценарий «товар сняли»: КОГДА после добавления товар сняли с показа ТОГДА его строки нет на /cart/, итог и счётчик без него

## Требование: изменение количества
Система ДОЛЖНА менять количество кнопками «−» и «+»: с JS блок строк, итог и счётчик в шапке обновляются без перезагрузки, фокус остаётся на нажатой кнопке; без JS — отправка формы и возврат на /cart/. Уменьшение до 0 удаляет строку так же, как «Удалить». Больше 99 не ставится.

- Сценарий «плюс»: КОГДА пользователь на /cart/ нажимает «+» у строки с количеством 1 ТОГДА количество 2, сумма строки и итог пересчитаны
- Сценарий «до нуля»: КОГДА пользователь нажимает «−» у строки с количеством 1 ТОГДА строка исчезает, появляется «<название> удалён из корзины» и «Вернуть»
- Сценарий «мусор»: КОГДА клиент делает POST /cart/update/ с quantity=abc ТОГДА количество строки становится 1
- Сценарий «сверх предела»: КОГДА клиент делает POST /cart/update/ с quantity=150 ТОГДА количество 99
- Сценарий «неизвестная строка»: КОГДА клиент делает POST /cart/update/ с несуществующим line_id ТОГДА корзина не меняется, переход на /cart/
- Сценарий «не тот метод»: КОГДА клиент делает GET /cart/update/ ТОГДА получает 405

## Требование: удаление и возврат
Система ДОЛЖНА по «Удалить» убирать строку и показывать «<название> удалён из корзины» с кнопкой «Вернуть» (с JS сообщение исчезает через 10 с; без JS показывается один раз на /cart/ после перехода). «Вернуть» восстанавливает последнюю удалённую строку с тем же количеством и цветами; если такая же строка уже снова добавлена, количества складываются (не больше 99). Запоминается только одна последняя удалённая строка.

- Сценарий «удалить и вернуть»: КОГДА пользователь удаляет строку «Кресло × 2, Графит» и жмёт «Вернуть» ТОГДА строка возвращается с количеством 2 и цветом «Графит»
- Сценарий «без JS»: КОГДА JS выключен и пользователь жмёт «Удалить» ТОГДА после перезагрузки /cart/ видит сообщение и «Вернуть», при следующем открытии /cart/ сообщения нет
- Сценарий «две подряд»: КОГДА пользователь удаляет две строки подряд и жмёт «Вернуть» ТОГДА возвращается только вторая
- Сценарий «нечего возвращать»: КОГДА клиент делает POST /cart/undo/ без предыдущего удаления ТОГДА корзина не меняется
- Сценарий «повторный возврат»: КОГДА пользователь второй раз отправляет «Вернуть» ТОГДА ничего не добавляется
- Сценарий «возврат после оформления»: КОГДА пользователь удалил строку, затем оформил заявку ТОГДА возвращать нечего

## Требование: пустая корзина
Система ДОЛЖНА при пустой корзине показывать «В корзине пока пусто», пояснение и «Продолжить покупки» на /catalog/; на странице /cart/ дополнительно три пункта доверия (ручная работа, гарантия 3 года, доставка по России) и «Вам может понравиться» из 4 хитов; в выезжающей панели — только сообщение и кнопку.

- Сценарий «пустая страница»: КОГДА пользователь без корзины открывает /cart/ ТОГДА видит «В корзине пока пусто», пункты доверия и до 4 карточек хитов
- Сценарий «удалена последняя строка»: КОГДА пользователь с JS удаляет последнюю строку на /cart/ ТОГДА появляется пустое состояние, хиты подгружаются следом

## Требование: счётчик корзины в шапке
Система ДОЛЖНА показывать у значка корзины сумму количеств по показываемым позициям, скрывать его при нуле и обновлять после каждого действия с корзиной без перезагрузки. Любой ответ на POST сбрасывает заранее скачанные браузером страницы, чтобы переход не показал старый счётчик.

- Сценарий «добавление»: КОГДА пользователь добавляет 2 штуки товара ТОГДА у значка корзины «2»
- Сценарий «ноль»: КОГДА корзина пуста ТОГДА счётчик скрыт
- Сценарий «снятый товар»: КОГДА в корзине 1 штука одного товара и 3 штуки снятого ТОГДА счётчик показывает 1
- Сценарий «сброс предзагрузки»: КОГДА клиент делает любой POST на сайт ТОГДА в ответе заголовок Clear-Site-Data: "prefetchCache"
