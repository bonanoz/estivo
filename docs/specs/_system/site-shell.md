# Каркас сайта

Общие части всех страниц: шапка с меню и счётчиками, мобильное меню, подвал, промо-полоса, плавающая кнопка связи, хлебные крошки, сообщения после форм, страницы ошибок 404/410/500 и предзагрузка страниц при наведении.

## Требование: шапка и меню
Система ДОЛЖНА на каждой странице, кроме оформления заявки, показывать закреплённую шапку: логотип (ссылка на /), меню «Каталог, Бизнесу, Дизайнерам, О нас, Доставка, FAQ, Контакты» (от 1024px — строкой, ниже — кнопкой «Меню»), кнопку поиска, значки избранного и корзины со счётчиками, телефон на широких экранах. Мобильное меню и окно поиска закрываются Esc с возвратом фокуса и блокируют прокрутку страницы под собой.

- Сценарий «десктоп»: КОГДА пользователь открывает / на ширине 1440px ТОГДА видит меню строкой и телефон +7 927 268-94-04
- Сценарий «мобильное меню»: КОГДА пользователь на 390px нажимает «Меню» ТОГДА открывается список разделов и кнопка телефона, страница под ним не прокручивается
- Сценарий «Esc»: КОГДА мобильное меню открыто и пользователь жмёт Esc ТОГДА меню закрыто, фокус на кнопке «Меню»
- Сценарий «пропуск навигации»: КОГДА пользователь первым нажатием Tab попадает на «Перейти к содержимому» и жмёт Enter ТОГДА фокус переходит к основному содержимому

## Требование: подвал
Система ДОЛЖНА показывать в подвале логотип, описание, оценку покупателей «N из 5 · отзывов: N» (только если есть опубликованные отзывы), соцсети, «Популярное» — до 12 ссылок на разделы «<категория> из <материала>» с показываемыми товарами, «Покупателям» (о нас, доставка, гарантия, FAQ, бизнес, дизайнеры, контакты, «Настройки cookie»), контакты, часы работы и реквизиты ООО «Эстиво» со ссылкой на политику. Данные подвала обновляются с задержкой до 5 минут.

- Сценарий «рейтинг»: КОГДА опубликованы отзывы с оценками 4 и 5 ТОГДА в подвале «Оценка покупателей: 4,5 из 5 · отзывов: 2» (не позже чем через 5 минут)
- Сценарий «нет отзывов»: КОГДА опубликованных отзывов нет ТОГДА строки с оценкой нет
- Сценарий «неопубликованные»: КОГДА есть только неопубликованные отзывы ТОГДА они не учитываются в оценке
- Сценарий «разделы»: КОГДА пользователь нажимает «Кресла из ротанга» в «Популярном» ТОГДА открывается /catalog/rotang/kresla/

## Требование: промо-полоса
Система ДОЛЖНА показывать над шапкой полосу с текстом из настроек сайта, только если она включена и текст не пустой; при заданной ссылке текст ведёт по ней. Кнопка «Закрыть сообщение» скрывает полосу, и она не появляется после перезагрузки, пока текст не изменится. Ссылка принимает только путь сайта или http(s)-адрес.

- Сценарий «полоса»: КОГДА в админке включена полоса с текстом «Скидки на роуп» и ссылкой /catalog/roup/ ТОГДА над шапкой ссылка «Скидки на роуп» на /catalog/roup/
- Сценарий «закрытие»: КОГДА пользователь закрыл полосу и перезагрузил страницу ТОГДА полосы нет без мигания
- Сценарий «новый текст»: КОГДА менеджер сменил текст полосы ТОГДА закрывший её пользователь снова видит полосу
- Сценарий «выключена»: КОГДА полоса выключена или текст пустой ТОГДА полосы нет
- Сценарий «опасная ссылка»: КОГДА менеджер вводит в админке ссылку javascript:alert(1) или //evil.example ТОГДА сохранение отклоняется с подсказкой о формате

## Требование: кнопка связи
Система ДОЛЖНА на каждой странице, включая оформление заявки, показывать круглую кнопку «Связаться с нами», раскрывающую «Написать в Telegram», «Написать в WhatsApp» и «Позвонить: +7 927 268-94-04»; работает без JS, Esc закрывает. На телефоне на страницах с формами (корзина, оформление, контакты, бизнес, дизайнеры, товар без цены) кнопка стоит в конце страницы, а не поверх формы.

- Сценарий «раскрытие»: КОГДА пользователь нажимает кнопку связи ТОГДА видит три ссылки
- Сценарий «форма на телефоне»: КОГДА пользователь открывает /kontakty/ на 390px ТОГДА кнопка связи не перекрывает поля и кнопку формы

## Требование: хлебные крошки и сообщения
Система ДОЛЖНА на всех страницах, кроме главной и оформления, показывать крошки «Главная / … / <текущая>» с последним пунктом без ссылки; сообщения после форм (успех лида, отзыва без JS) выводятся один раз над содержимым следующей страницы.

- Сценарий «крошки»: КОГДА пользователь открывает /garantiya/ ТОГДА видит «Главная / Гарантия», «Гарантия» без ссылки
- Сценарий «сообщение один раз»: КОГДА после отправки лида пользователь видит «Заявка отправлена!» и обновляет страницу ТОГДА сообщения нет

## Требование: страницы ошибок
Система ДОЛЖНА на неизвестный адрес (не из карты Tilda) отвечать 404 «Страница не найдена» с кнопками «Перейти в каталог», «На главную» и «Хиты продаж» до 8 карточек; на удалённые адреса Tilda — 410 «Страница удалена»; при ошибке сервера — статичную страницу «Ошибка сервера» без обращения к базе.

- Сценарий «404»: КОГДА пользователь открывает /xyz-net/ ТОГДА статус 404, «Страница не найдена» и карточки хитов
- Сценарий «410»: КОГДА пользователь открывает адрес демо-товара Tilda из карты со статусом 410 ТОГДА статус 410 и «Страница удалена»
- Сценарий «404 без хитов»: КОГДА нет ни хитов, ни товаров для главной ТОГДА 404 без блока «Хиты продаж»

## Требование: предзагрузка страниц
Система ДОЛЖНА разрешать браузеру заранее скачивать страницы сайта при наведении на ссылку, кроме /cart/…, /order/…, /wishlist/…, /cookie-consent/ и ссылок, помеченных как исключение.

- Сценарий «наведение»: КОГДА пользователь в Chromium наводит курсор на ссылку /catalog/ ТОГДА страница скачивается заранее
- Сценарий «корзина»: КОГДА пользователь наводит на ссылку /cart/ ТОГДА предзагрузки нет
