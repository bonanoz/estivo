# Каталог

Списки товаров: общий каталог, разделы «материал» и «материал + категория», фильтры, сортировка, пагинация, живой счётчик, поиск (полная выдача и подсказки в шапке), промо-карточки акций и карточка товара в списках.

## Требование: разделы каталога
Система ДОЛЖНА показывать в каталоге только товары, отмеченные в админке как показываемые на сайте: в /catalog/ — все, в /catalog/<материал>/ — товары этого материала, в /catalog/<материал>/<категория>/ — товары материала и категории. Заголовок, хлебные крошки и строка «Товаров: N» соответствуют разделу. Неизвестный материал или категория в пути дают страницу 404.

- Сценарий «общий каталог»: КОГДА пользователь открывает /catalog/ ТОГДА видит H1 «Вся мебель», строку «Товаров: N» и карточки всех показываемых товаров
- Сценарий «раздел материала»: КОГДА пользователь открывает /catalog/rotang/ ТОГДА видит H1 «Ротанг», только товары из ротанга и крошки «Главная / Каталог / Ротанг»
- Сценарий «материал и категория»: КОГДА пользователь открывает /catalog/rotang/kresla/ ТОГДА видит H1 «Кресла из ротанга», крошки со ссылкой на /catalog/rotang/ и только кресла из ротанга
- Сценарий «пара без товаров»: КОГДА пользователь открывает существующие материал и категорию, у которых нет общих товаров ТОГДА получает 200 и блок «Ничего не найдено»
- Сценарий «неизвестный материал»: КОГДА пользователь открывает /catalog/nesuschestvuet/ ТОГДА получает 404 «Страница не найдена» (если пути нет в карте редиректов Tilda)
- Сценарий «снятый товар»: КОГДА менеджер снимает товар с показа в админке ТОГДА товар пропадает из /catalog/ и всех разделов

## Требование: фильтры
Система ДОЛЖНА фильтровать выдачу GET-параметрами: категория, материал (только в общем каталоге), цвет, цена от/до, длина от/до (границы включительно), подборки «Новинки», «Хиты продаж», «Со скидкой». Несколько значений одного параметра объединяются через «или», товары не дублируются. Мусорные значения молча игнорируются. Фильтры применяются кнопкой «Применить», «Сбросить» ведёт на тот же путь без параметров, отмеченные значения видны в форме после применения.

- Сценарий «цена»: КОГДА пользователь открывает /catalog/?price_min=10000&price_max=50000 ТОГДА видит товары с ценой от 10 000 до 50 000 ₽ включительно, поля «От, ₽» и «До, ₽» заполнены
- Сценарий «несколько категорий»: КОГДА пользователь открывает /catalog/?category=kresla&category=divany ТОГДА видит кресла и диваны вместе, оба чекбокса отмечены
- Сценарий «цвет»: КОГДА пользователь открывает /catalog/?color=<id цвета> ТОГДА видит только товары с этим цветом, каждый один раз
- Сценарий «скидка»: КОГДА пользователь открывает /catalog/?flag=sale ТОГДА видит только товары, у которых старая цена выше текущей
- Сценарий «фильтр в разделе»: КОГДА пользователь открывает /catalog/rotang/?flag=new ТОГДА видит новинки только из ротанга, а группы «Материал» в панели нет
- Сценарий «число активных»: КОГДА применены два фильтра ТОГДА кнопка панели показывает «Фильтры · 2»
- Сценарий «сброс»: КОГДА пользователь на /catalog/rotang/?flag=new нажимает «Сбросить» ТОГДА открывается /catalog/rotang/ без параметров
- Сценарий «без JS»: КОГДА JS выключен и пользователь отмечает фильтр и жмёт «Применить» ТОГДА страница перезагружается с параметрами в адресе
- Сценарий «мусор в адресе»: КОГДА пользователь открывает /catalog/?price_min=abc&color=xyz&flag=foo&category=nope ТОГДА получает 200 и полный список, ни один фильтр не отмечен
- Сценарий «отрицательная граница»: КОГДА пользователь открывает /catalog/?price_min=-5 ТОГДА граница игнорируется
- Сценарий «материал в адресе раздела»: КОГДА пользователь открывает /catalog/rotang/?material=roup ТОГДА параметр игнорируется и показан ротанг

## Требование: живой счётчик фильтров
Система ДОЛЖНА при изменении значений в панели фильтров (с паузой около 0,3 с) обновлять строку «Найдено: N» под текущие значения без перезагрузки и без смены карточек; на страницах раздела число учитывает материал и категорию из пути. Счётчик доступен отдельным адресом /catalog/count/ и отвечает коротким фрагментом.

- Сценарий «отметка фильтра»: КОГДА пользователь на /catalog/ открывает панель и отмечает «Новинки» ТОГДА текст «Найдено: N» меняется, сетка карточек остаётся прежней до «Применить»
- Сценарий «раздел»: КОГДА пользователь на /catalog/rotang/ меняет цену в панели ТОГДА число считается только по ротангу
- Сценарий «прямой запрос»: КОГДА клиент делает GET /catalog/count/?flag=new ТОГДА получает фрагмент «Найдено: N», а не страницу
- Сценарий «мусор»: КОГДА клиент делает GET /catalog/count/?price_min=abc ТОГДА получает число всех показываемых товаров
- Сценарий «не тот метод»: КОГДА клиент делает POST /catalog/count/ ТОГДА получает 405

## Требование: сортировка
Система ДОЛЖНА сортировать выдачу по выбору «Рекомендуемые» (по умолчанию: сначала товары для главной, затем по названию), «Сначала дешевле», «Сначала дороже», «Новинки» (сначала новинки, затем новые записи). С JS выбор применяется сразу, без JS — кнопкой «Показать». Выбранное значение отмечено в списке, сортировка сохраняется вместе с фильтрами.

- Сценарий «дешевле»: КОГДА пользователь открывает /catalog/?sort=price_asc ТОГДА цены идут по возрастанию, в списке выбрано «Сначала дешевле»
- Сценарий «дороже»: КОГДА пользователь выбирает «Сначала дороже» в списке на /catalog/?flag=new ТОГДА страница перезагружается с sort=price_desc и flag=new
- Сценарий «неизвестное значение»: КОГДА пользователь открывает /catalog/?sort=xxx ТОГДА порядок по умолчанию и выбрано «Рекомендуемые»

[?] «Сначала дешевле» ставит первыми товары «Цена по запросу» (цена 0), catalog_filters.py:15

## Требование: пагинация
Система ДОЛЖНА выводить по 24 товара на страницу и нумерованную навигацию «Страницы» с первой, последней, соседними страницами и многоточием; текущая страница помечена; ссылки сохраняют фильтры, сортировку и поиск без дублирования параметра страницы. При одной странице навигации нет.

- Сценарий «вторая страница»: КОГДА при 30 товарах пользователь открывает /catalog/?page=2 ТОГДА видит 6 карточек и помеченную страницу 2
- Сценарий «фильтры в ссылках»: КОГДА пользователь на /catalog/?flag=new&sort=price_asc переходит на страницу 2 ТОГДА в адресе остаются flag и sort, page встречается один раз
- Сценарий «страница за пределами»: КОГДА пользователь открывает /catalog/?page=999 ТОГДА видит последнюю страницу
- Сценарий «мусор вместо номера»: КОГДА пользователь открывает /catalog/?page=abc ТОГДА видит первую страницу
- Сценарий «одна страница»: КОГДА товаров 24 или меньше ТОГДА навигации по страницам нет

## Требование: пустая выдача
Система ДОЛЖНА при нуле товаров показывать «Ничего не найдено», совет изменить фильтры, кнопки «Сбросить фильтры» (тот же путь без параметров) и «Оставить заявку» (на /kontakty/), а ниже блок «Хиты продаж» из 4 карточек (хиты, при их отсутствии — товары для главной).

- Сценарий «пусто»: КОГДА пользователь открывает /catalog/?price_min=99999999 ТОГДА видит «Ничего не найдено», обе кнопки и «Хиты продаж»
- Сценарий «нет хитов»: КОГДА в базе нет ни хитов, ни товаров для главной ТОГДА блок «Хиты продаж» не выводится

## Требование: поиск по каталогу
Система ДОЛЖНА по адресу /catalog/?search=<текст> показывать показываемые товары, в названии или описании которых встречается текст без учёта регистра, с заголовком «Поиск: «<текст>»». Запрос сохраняется при применении фильтров, сортировки и перелистывании.

- Сценарий «поиск»: КОГДА пользователь открывает /catalog/?search=кресло ТОГДА видит H1 «Поиск: «кресло»» и только совпадения
- Сценарий «поиск и фильтр»: КОГДА пользователь на странице поиска применяет фильтр ТОГДА параметр search остаётся в адресе
- Сценарий «пустой запрос»: КОГДА пользователь открывает /catalog/?search= ТОГДА видит обычный каталог «Вся мебель»
- Сценарий «нет совпадений»: КОГДА пользователь открывает /catalog/?search=zzzz ТОГДА видит «Ничего не найдено» и «Хиты продаж»

[?] Подсказки ищут ещё и по артикулу (views.py:217), а полная выдача «Все результаты» — только по названию и описанию (views.py:178-179): товар, найденный в подсказке по артикулу, пропадает в /catalog/?search=; полная выдача к тому же не обрезает пробелы в запросе (views.py:184), подсказки обрезают (views.py:212)

## Требование: подсказки поиска в шапке
Система ДОЛЖНА по кнопке с лупой открывать окно поиска; при вводе от 2 символов (пауза около 0,25 с) показывать до 6 показываемых товаров, найденных по названию, артикулу или описанию, со строкой «фото, название, цена» и кнопкой «Все результаты». Если ничего нет — «Ничего не найдено», «Возможно, вам понравится» с хитами и «Открыть каталог». Enter ведёт на /catalog/?search=<текст>, Esc закрывает окно.

- Сценарий «подсказки»: КОГДА пользователь на / нажимает лупу и вводит «кре» ТОГДА появляются до 6 строк товаров и «Все результаты»
- Сценарий «Enter»: КОГДА пользователь вводит «кресло» и жмёт Enter ТОГДА открывается /catalog/?search=кресло
- Сценарий «Esc»: КОГДА окно поиска открыто и пользователь жмёт Esc ТОГДА окно закрывается, фокус возвращается на кнопку поиска
- Сценарий «один символ»: КОГДА клиент делает GET /search/suggest/?q=к ТОГДА ответ пустой
- Сценарий «нет совпадений»: КОГДА клиент делает GET /search/suggest/?q=zzzz ТОГДА видит «Ничего не найдено», до 4 рекомендаций и «Открыть каталог»
- Сценарий «снятый товар»: КОГДА совпадение есть только у снятого с показа товара ТОГДА в подсказках его нет

## Требование: промо-карточки акций
Система ДОЛЖНА при подборке «Со скидкой» показывать над сеткой до 3 карточек акций: товары с ценой, старой ценой выше текущей и датой окончания акции не раньше сегодняшней, по возрастанию даты. В карточке обе цены, «Выгода N ₽», «Акция до <дата>» и кнопка «Узнать цену <название>» на /kontakty/?product=<slug>. Без даты или после неё карточка не показывается.

- Сценарий «действующая акция»: КОГДА пользователь открывает /catalog/?flag=sale и у товара акция до завтра ТОГДА над сеткой видна карточка с обеими ценами и датой
- Сценарий «акция закончилась»: КОГДА дата окончания вчерашняя ТОГДА промо-карточки нет, товар остаётся в общей сетке со скидкой
- Сценарий «без подборки»: КОГДА пользователь открывает /catalog/ без flag=sale ТОГДА промо-карточек нет

[?] Промо-карточки берутся из всего каталога и не учитывают раздел и остальные фильтры: на /catalog/roup/?flag=sale видны акции ротанга, а товар акции дублируется в общей сетке, views.py:159-163

## Требование: текст раздела и вопросы под сеткой
Система ДОЛЖНА под сеткой показывать текст о разделе (описание материала, если оно есть, иначе общий текст о плетёной мебели), шесть частых вопросов раскрывающимися блоками, строку фактов (гарантия, срок изготовления, доставка ТК, работа по договору) и блок «Обсудим вашу мебель?» со ссылкой на /kontakty/ и телефоном.

- Сценарий «раздел с описанием»: КОГДА пользователь открывает /catalog/rotang/ ТОГДА видит заголовок «Мебель из материала «ротанг»» и описание материала
- Сценарий «без описания»: КОГДА у материала пустое описание ТОГДА выводится общий текст о роупе и ротанге

## Требование: карточка товара в списках
Система ДОЛЖНА показывать в карточке фото (или заглушку) с названием в alt, бейджи «Новинка», «Хит», «Скидка» (старая цена выше текущей), материал и категорию, название-ссылку на товар, до 4 цветовых точек и «+N» за остальные, цену «от N ₽» и зачёркнутую старую цену. У товара с нулевой ценой — «Цена по запросу» и ссылка «Узнать цену» на /kontakty/?product=<slug>, без добавления в корзину.

- Сценарий «много цветов»: КОГДА у товара 6 цветов ТОГДА видны 4 точки и «+2»
- Сценарий «ровно четыре»: КОГДА у товара 4 цвета ТОГДА «+N» нет
- Сценарий «скидка»: КОГДА старая цена выше текущей ТОГДА есть бейдж «Скидка» и зачёркнутая старая цена
- Сценарий «старая цена не выше»: КОГДА старая цена равна текущей или ниже ТОГДА нет ни бейджа, ни зачёркнутой цены
- Сценарий «цена по запросу»: КОГДА цена товара 0 ТОГДА карточка показывает «Цена по запросу» и «Узнать цену», кнопки корзины нет
- Сценарий «нет фото»: КОГДА у товара нет фото ТОГДА показана заглушка с названием товара в alt
