# Аналитика и согласие на cookie

Полоса согласия на cookie, подключение Яндекс Метрики только после согласия, цели и e-commerce-данные для Метрики, источник захода (utm, yclid, страница входа) в заявках и лидах.

## Требование: согласие на cookie
Система ДОЛЖНА показывать полосу «Используем cookie и Яндекс Метрику. Подробнее» (ссылка на /privacy/#cookie) с кнопками «Принять все» и «Принять обязательные», пока выбор не сделан или пока в адресе есть ?cookie_settings=1 (ссылка «Настройки cookie» в подвале). Выбор хранится год. С JS полоса уходит без перезагрузки, без JS — переход обратно на страницу. Неизвестный выбор даёт 400.

- Сценарий «первый заход»: КОГДА пользователь впервые открывает / ТОГДА видит полосу cookie, а в коде страницы нет счётчика Метрики
- Сценарий «принять все»: КОГДА пользователь жмёт «Принять все» ТОГДА полоса исчезает, счётчик 93915751 подключается без перезагрузки, на следующих страницах полосы нет
- Сценарий «только обязательные»: КОГДА пользователь жмёт «Принять обязательные» ТОГДА полоса исчезает, счётчика нет ни сейчас, ни после перезагрузки
- Сценарий «настройки»: КОГДА пользователь с выбором нажимает «Настройки cookie» в подвале ТОГДА полоса показана снова
- Сценарий «без JS»: КОГДА JS выключен и пользователь на /garantiya/ жмёт «Принять обязательные» ТОГДА возвращается на /garantiya/
- Сценарий «чужой адрес возврата»: КОГДА клиент делает POST /cookie-consent/ с next=https://evil.example/ ТОГДА переход на /
- Сценарий «неизвестный выбор»: КОГДА клиент делает POST /cookie-consent/ с choice=all ТОГДА получает 400
- Сценарий «не тот метод»: КОГДА клиент делает GET /cookie-consent/ ТОГДА получает 405

[?] Без JS возврат идёт на путь без параметров: после выбора на /catalog/?flag=sale или /kontakty/?product=… фильтры и предзаполнение теряются (_cookie_banner.html:4)

## Требование: цели и e-commerce
Система ДОЛЖНА объявлять на каждой странице очередь данных для Метрики и класть в неё: просмотр товара на /product/<slug>/, добавление в корзину после добавления с JS, покупку на /order/success/ один раз (номер заявки, сумма, позиции). Цели «checkout_submit», «lead_submit_<тип>», «price_request» передаются на странице после перехода и один раз; ссылки на телефон, Telegram, WhatsApp и Max помечены целями кликов.

- Сценарий «просмотр товара»: КОГДА пользователь открывает /product/<slug>/ ТОГДА в коде страницы данные detail с id, названием, ценой и категорией
- Сценарий «покупка»: КОГДА пользователь отправил заявку ТОГДА на /order/success/ данные purchase с номером и суммой, после F5 их нет
- Сценарий «цель лида»: КОГДА пользователь отправил форму на /b2b/ ТОГДА на следующей странице одна цель lead_submit_b2b, на следующей за ней — ни одной
- Сценарий «цель запроса цены»: КОГДА пользователь отправил «Узнать цену» ТОГДА переданы lead_submit_private и price_request
- Сценарий «без заявки»: КОГДА пользователь сразу открывает /order/success/ ТОГДА данных purchase нет

## Требование: источник захода
Система ДОЛЖНА при первом обычном просмотре страницы в сессии запоминать utm_source, utm_medium, utm_campaign, utm_content, utm_term, yclid и страницу входа и больше их не перезаписывать; при отправке заявки или лида записывать их в запись вместе с идентификатором Метрики из cookie _ym_uid (только цифры, до 64 знаков). Технические запросы (статика, медиа, админка, sitemap, robots, фоновые запросы htmx) не учитываются. Анонимный заход без меток сессию не создаёт.

- Сценарий «первый вход с метками»: КОГДА пользователь заходит на /?utm_source=a&utm_campaign=b&yclid=123, переходит в каталог и отправляет заявку ТОГДА в заявке utm_source=a, utm_campaign=b, yclid=123, страница входа «/?utm_source=a&utm_campaign=b&yclid=123»
- Сценарий «повторный вход»: КОГДА тот же пользователь заходит снова по ссылке с utm_source=c ТОГДА в заявке остаётся utm_source=a
- Сценарий «идентификатор Метрики»: КОГДА у пользователя cookie _ym_uid=42 ТОГДА в лиде идентификатор 42
- Сценарий «мусорный идентификатор»: КОГДА cookie _ym_uid=abc ТОГДА поле пустое
- Сценарий «без меток»: КОГДА пользователь без меток открывает / ТОГДА cookie сессии не выставляется
- Сценарий «Telegram»: КОГДА заявка пришла без меток ТОГДА в уведомлении «Источник: прямой заход, вход <страница>»

[?] Без меток первый заход атрибуцию не пишет (сессии ещё нет); страница входа записывается на первом GET после того, как сессия появилась, обычно после первого «В корзину» (например, /cart/), а не на реальной странице входа; tilda-migration/SPEC.md:262 требует «landing_page = первый URL» (middleware.py:48)
